# Changelog

## 0.1.11-alpha

Borsh wRPC client beside the existing JSON client.

- `KaspaRpcClient.Create` with `KaspaRpcEncoding.Auto` reads the URL path before the port. The path wins. A path ending in `/wrpc/borsh` or containing `/borsh` selects Borsh. A path ending in `/wrpc/json` or containing `/json` selects JSON. Borsh is tested first. The match is ordinal and case-insensitive, and trailing slashes are ignored for the ending check. `wss://host/kaspa/mainnet/wrpc/json` on port 443 selects JSON. An explicit `KaspaRpcEncoding.Borsh` or `Json` still overrides the path and a wRPC port.
- When the path has no hint and the port is not a default wRPC port, `Create` still throws. NKaspa does not default to Borsh or JSON. `wss` on port 443 with no `/borsh` or `/json` hint is that case.
- gRPC ports 16110, 16210, 16510, and 16610 throw `ArgumentException`. The message says NKaspa speaks wRPC (Borsh 17110/17210/17510/17610 or JSON 18110/18210/18510/18610), not gRPC. An explicit encoding does not turn those ports into wRPC. `KaspaWrpcPorts` records the four gRPC ports and `TrySelectPath`.
- A JSON client that receives a binary frame, or a Borsh client that receives a text frame, throws `KaspaRpcEncodingMismatchException`. A JSON handshake text frame on a Borsh client sets `HandshakeFailed`. Pending requests fail with that exception. The client does not wait for the request timeout and does not reconnect.
- The English README has an FAQ, and the NuGet description and tags name C#, .NET, the SDK, wallets, BIP39, BIP32, and wRPC JSON and Borsh. English tutorials live under `docs/tutorials/`. `samples/Tutorials` compiles those snippets and stays offline. `docs/NBitcoin-Mapping.en.md` is the English map.
- `KaspaWrpcBorshClient` speaks rusty-kaspa workflow-rpc Borsh on a binary WebSocket. The layout follows rusty-kaspa `4edcbbccb449f84832afb1ca157904b35f37d006` and workflow-rs `7e2958098bbe0647adcfcc0dfc174e438a60699e` (workflow-rpc and workflow-serializer 0.19.0). A request is a `BorshReqHeader` (optional u64 id, `RpcApiOps` as one byte) plus a length-prefixed versioned serializer body. A success response is a Borsh `Result` around that body. borsh 1.8.1 writes `Ok` as `1u8` and `Err` as `0u8`. A notification is a length-prefixed `Notification` serializer, not a `Result`.
- `KaspaRpcClient.Create(url, encoding = Auto)` returns a `KaspaRpcConnection` and does not connect. After the path check above, Auto selects Borsh for 17110 (mainnet), 17210 (testnet), 17510 (simnet), and 17610 (devnet), and JSON for 18110, 18210, 18510, and 18610. Simnet is 17510 and 18510. It is not 17310 or 18310.
- The Borsh socket uses the same connect and request timeouts, reconnect policy, 16 MiB frame cap, `State`, `StateChanged`, and `Reconnected` behavior as the JSON socket.
- `IKaspaRpcClient` adds `GetBalancesByAddressesAsync`, `NotifyUtxosChangedAsync`, `NotifyVirtualDaaScoreChangedAsync`, and `NotifyBlockAddedAsync`. The JSON client implements them too. Subscriptions send workflow-rpc `Subscribe` (op 3) and `Unsubscribe` (op 4) with a `Scope`. The node router does not register the older `Notify*` ops. Disposing the `KaspaSubscription` stops that scope.
- Fee-estimate buckets are confirmed in rusty-kaspa `rpc/core/src/model/feerate_estimate.rs`: a required `priorityBucket`, then `normalBuckets` and `lowBuckets`. Each bucket is `feerate` and `estimatedSeconds` as two little-endian f64 values.
- Tests cover hand-computed Borsh frames for each request and response (cargo was not available), a fake Borsh WebSocket round trip, a subscription notification, and port auto-selection. `SubmitTransaction` is sent only to that fake server.
- `RpcBlockDagInfo.BlueScore` is optional JSON. rusty-kaspa `GetBlockDagInfoResponse` in `rpc/core/src/model/message.rs` has no `blueScore`. Borsh order stays `network`, `blockCount`, `headerCount`, `tipHashes`, `difficulty`, `pastMedianTime`, `virtualParentHashes`, `pruningPointHash`, `virtualDaaScore`, `sink`. A missing JSON field is 0. `GetBlockDagInfoAsync` does not call `getSinkBlueScore`.
- `GetSinkBlueScoreAsync` is `getSinkBlueScore`, Borsh op 138. The response is serializer version 1, then `blueScore` as u64. That is the blue score of the virtual selected parent (the sink).
- `GetVirtualChainFromBlockAsync` is `getVirtualChainFromBlock`, Borsh op 128. The request serializer is version 2: `startHash`, `includeAcceptedTransactionIds`, and `minConfirmationCount` as a Borsh option. The response is version 1: `removedChainBlockHashes`, `addedChainBlockHashes`, `acceptedTransactionIds`. It has no blue score. `GetVirtualChainFromBlockV2` (op 151) is not implemented.
- Header `blueWork` is rusty-kaspa `BlueWorkType` (`Uint192` in `rpc/core/src/model/header.rs`): 24 little-endian bytes. JSON hex may omit leading zeros. `RpcChainBlock.BlueWork` and `RpcBlockAdded.BlueWork` store those bytes when the field is present. Header `blueScore` was already on `getBlock`.
- `ConsensusParams` is coinbase maturity in DAA score. rusty-kaspa `consensus/core/src/config/params.rs` uses `Bps::coinbase_maturity` (`bps.rs`), which is `BPS * COINBASE_MATURITY_SECONDS` (`constants.rs`, 100 seconds). Mainnet is 100 before DAA 110165000 and 1000 at and after it. Testnet-10 (`Network.Testnet`) is 100 before 88657000 and 1000 after. Simnet and devnet are `ForkActivation::always()` at 10 BPS, so maturity is 1000 at every score. Current master has no `TESTNET11_PARAMS`. Historical testnet-11 used 1000 (`kaspawallet` `25c2dd86709b5a0b889785e7e6b0c00c8827a8b7`). `ConsensusParams.Testnet11` records that. `ForNetwork` does not map the name `testnet` to it. `IsCoinbaseMature` and `SpendableAtDaaScore` use this schedule. A live `TransactionValidator` stores `params.coinbase_maturity()`, the post-blockrate 1000.
- `WalletKeystore` encrypts a mnemonic or a seed with a password. The KDF is PBKDF2-HMAC-SHA256, 600000 iterations unless the caller passes another positive count. Argon2 is not in the .NET base class library, so no package was added. The cipher is AES-256-GCM. JSON fields, in order, are `version`, `kdf`, `kdfParams`, `cipher`, `salt`, `nonce`, `tag`, and `ciphertext`. `KeystoreSecret.ToString` returns `NKaspa.KeystoreSecret`. A wrong password throws `WrongKeystorePasswordException` with the message `Wrong keystore password.`
- `FeeEstimator` estimates compute mass, KIP-9 storage mass, and the fee for a transaction shape without private keys. A version-0 Schnorr pay-to-pubkey payment with one input and two outputs has compute mass 2036, the same mass as the signed transaction. The placeholder signature script is 66 bytes. `DefaultMinimumFeerateSompiPerGram` is 100. `MinimumFeerate` reads the lowest positive finite `getFeeEstimate` bucket and rounds it up. `PayableFeerate` raises a lower bucket to 100. `ReadMinimumFeerateAsync` returns the node bucket without that floor.
- `KeystoreSecret.Reveal` returns the phrase, or lowercase hex for seed bytes. `Clear` zeros the buffer, the same as `Dispose`. `ToString` stays `NKaspa.KeystoreSecret`. System.Text.Json refuses the type, including when `allowPrivateKeys` is true. Newtonsoft.Json is not a package reference. `ShouldSerializeIsPhrase` throws `Refusing to convert KeystoreSecret.` for a caller that references it. `Key.ToString` is `NKaspa.Key`. `Key.Reveal`, `Mnemonic.Reveal`, and `ExtKey.Reveal` return a `KeystoreSecret`. `Key.Clear` and `ExtKey.Clear` zero those keys. Wordlist strings cannot be wiped.
- `PersonalMessage.SignMessage` and `VerifyMessage` match rusty-kaspa `sign_message`. The digest is BLAKE2b-256 of the UTF-8 message, keyed with `PersonalMessageSigningHash` (`crypto/hashes/src/hashers.rs`). The signature is BIP-340. `VerifyMessage(KaspaAddress, ...)` accepts only a Schnorr pay-to-pubkey address and checks that the 32-byte payload is the signing key. ECDSA and script-hash addresses return false. Vectors are `wallet/core/src/message.rs` at `8fe466311ba179e74fc8a52f13b36140bb6b9a4e`. `samples/SignMessage` uses this API. An empty auxiliary span is random. Thirty-two explicit bytes, including zeros, are deterministic.
- wRPC failures a wallet can branch on are `KaspaWrpcException`. `KaspaNodeUnreachableException` wraps a connect or request timeout, a `WebSocketException`, an `IOException`, and an `InvalidOperationException` whose message contains `disconnected`. The message is `Kaspa node is unreachable.` The inner exception is the original failure. `KaspaWebSocketChannel` still throws `TimeoutException`. Borsh server error `connection is closed` uses that text. `KaspaWrongNetworkException` maps rusty-kaspa `NetworkIdError` and `NetworkTypeError` prefixes from `consensus/core/src/network.rs`. `KaspaNodeNotSyncedException` maps the exact `RpcError::ConsensusInTransitionalIbdState` sentence from `rpc/core/src/error.rs`. `KaspaUtxoIndexNotEnabledException` maps a message containing `--utxoindex`, the `RpcError::NoUtxoIndex` display text. `IKaspaRpcClient.EnsureReadyAsync` checks `getServerInfo` for network, sync, and the UTXO index. `GetServerInfoAsync` itself does not. `testnet-10` matches `Network.Testnet`. `KaspaRpcEncodingMismatchException`, `OperationCanceledException`, `ObjectDisposedException`, and a generic `KaspaRpcException` such as `nope` or `RPC call timed out` stay as they were.

## 0.1.10-alpha

Review follow-up on local main.

- Toccata activation DAA scores: mainnet 474165565 and testnet-10 467579632, from rusty-kaspa `90dbf074` `consensus/core/src/config/params.rs` lines 724 and 785. Current master removed the field.
- Pre-Toccata minimum relay fee is 1 sompi/gram (`LEGACY_MINIMUM_RELAY_TRANSACTION_FEE` at `90dbf074` `mining/src/mempool/config.rs` line 28). Post-Toccata default is 100. `FeeRate.MinimumRelay` and `MassCalculator.MinimumFeeRate` stay 100.
- Forcing pre-Toccata mode (`MassPolicy.PreToccata`, `toccataActive: false`, or a DAA below the activation score) yields 1 sompi/gram, which current (post-Toccata) nodes may reject; use the default policy for live networks.
- Earlier 0.1.10 review work: BIP39 checksum refusal on derive, folded-change cap, WebSocket frame bound, disconnect tests that reset the managed socket, and a single name for folded change.

### Breaking changes vs 0.1.9-alpha

- `Mnemonic.Words` is now `IReadOnlyList<string>` (read-only).
- `Mnemonic.ToString()` and `ExtKey.ToString()` no longer output plaintext secrets; use `ToPhrase()` / `ExportXprv()`.
- Derivation from a mnemonic with an invalid checksum now throws unless `allowInvalidChecksum: true` is passed.
- Default JSON serialization of `Key`, `ExtKey` and `Mnemonic` is refused; only `NKaspaJsonSerializer` with `allowPrivateKeys: true` serializes them.
- Mnemonics are normalized (NFKD, case-insensitive, zero-width characters/BOM stripped) before parsing.
- Change folded into the fee is capped at min(max(MinimumChange, 0.1 KAS), 100x fee); larger amounts throw. `ChangeFoldedIntoFee` replaces `ChangeFolded` / `FoldedChange`.
- With `toccataActive: false` the minimum relay fee rate is 1 sompi/gram.
